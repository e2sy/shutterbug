# THE PROMPT KIT
### rebuild "shutterbug." on camera — for the @mayankforge tutorial

This kit contains everything needed to recreate the whole website from
scratch, on video, with an AI coding agent (Z.ai, Claude, Cursor, or any
strong coding model): one one-shot mega-prompt, five phased prompts that
double as tutorial chapters, a narration build guide, a swap map so any
viewer can make the site theirs, and the YouTube extras.

**What's inside**

| Part | What it is | Use it for |
|------|------------|------------|
| A | The one-shot mega-prompt | the "AI built it in ONE prompt" hook |
| B | 5 phased prompts | the teaching chapters (one per part) |
| C | Build guide | what to demo, paste and check per chapter |
| D | Swap map | "make it yours in 6 edits" viewer homework |
| E | YouTube extras | titles, thumbnail, description, code callouts |

**How to run it**: create an empty folder, start the agent, paste Part A
whole (or run Part B's prompts one at a time for the tutorial), let it
build, then verify against the acceptance checklist at the end of each
prompt. Nothing else is required — the prompts generate their own assets.

## PART A — THE ONE-SHOT MEGA-PROMPT

Paste this entire block into the agent in one message:

```
ROLE
You are a senior creative developer who ships award-calibre, weirdly
polished web experiences. You write production-grade TypeScript, you
generate your own assets, and you finish what you start.

MISSION
Rebuild "shutterbug." — a single-page, scroll-driven filmmaker portfolio
that presents itself as a bootable black-and-white operating system. The
visitor boots the page, lands on a huge typographic hero, scrolls through
a film archive played on a real-time 3D handheld console whose CRT screen
runs generated motion reels, reads an about section, and exits through a
contact deck wired to real social links. Everything is grayscale, gritty
and alive. Build the WHOLE site in this one pass — shell, engine, sound,
machine, content and generated assets.

NON-NEGOTIABLES
1. ORIGINAL CODE. Do not fetch or clone any existing website's HTML,
   CSS or JS. Build from this spec with your own implementation.
2. ORIGINAL ASSETS. Every image, video and sound must be generated by
   you, locally, with Python (Pillow + numpy) and ffmpeg. No stock
   photos, no AI image APIs, no copyrighted music. Write the generator
   scripts into scripts/ so they can be re-run.
3. BLACK & WHITE DISCIPLINE. The entire site is pure grayscale. No hue
   anywhere: not in UI, not in artwork, not in the 3D scene lighting.
4. IT MUST FEEL LIKE HARDWARE. Every visible control on the 3D console
   is a live, clickable prototype control. Nothing is decorative.

STACK
- Next.js (App Router) + TypeScript, bun as the package manager, one
  route at "/".
- Plain CSS in one site.css file (no Tailwind). All design tokens live
  in :root as CSS custom properties.
- three (npm) for the 3D console, loaded with next/dynamic { ssr: false }.
- VT323 (SIL OFL) self-hosted in public/fonts for the VCR/HUD chrome.
- scripts/ holds the Python + ffmpeg asset generators.

ART DIRECTION
- Two inks only: #000 and #fff. Each section has a "paper" (background
  tone) and "ink" (foreground). Dark paper carries white ink, light
  paper carries black ink.
- Artwork cut-outs (stars, dice, CDs, badges) are black-on-transparent
  PNGs. They are inverted per paper (filter: invert) and mixed into the
  paper with mix-blend-mode: screen on dark, multiply on light, so the
  source rectangle never shows.
- Every section is a 16:9 "stage" that covers the viewport; type and
  cut-outs are positioned in stage percentages, not pixels.
- Type: "Helvetica Neue", Helvetica, Arial, sans-serif for display;
  VT323, ui-monospace for the HUD/VCR readouts.
- Motion character: slow, heavy, confident. Per-element parallax drift,
  soft staggered reveals, cubic-bezier(0.16, 1, 0.3, 1) easing, gentle
  idle sway on the 3D device. Respect prefers-reduced-motion everywhere.

ARCHITECTURE (build exactly these)
- src/app/layout.tsx — metadata (title "shutterbug.", description,
  inline SVG favicon, openGraph) + viewport with themeColor #ffffff.
- src/app/page.tsx — renders <Site/>.
- src/components/site/Site.tsx — the OS shell: boot loader, fixed HUD,
  audio engine + deck, scroll engine, and the four content sections.
- src/components/site/Machine.tsx — the Three.js handheld console.
- src/components/site/site.css — every rule, mobile breakpoints at the
  end, prefers-reduced-motion last.
- src/lib/sk.ts — a tiny dependency-free event bus singleton with:
  onReady/fireReady (boot handshake), setShellInvert(on) (shell polarity),
  toggleInvert() (console SELECT flips the page).
- src/lib/works.ts — typed channel data: { id, title, sub, kind, year,
  meta, img, vid?, link, vertical?, featured? }.
- public/assets/el (cut-outs + icons), public/assets/works (posters),
  public/assets/reels (mp4 loops), public/assets/audio (music).

FEATURE SPECS

1. BOOT LOADER. Full-screen fixed overlay in paper white with a pixel
   camera sprite, a 2px loading bar and a VT323 "000" percentage readout.
   The bar creeps toward 96% on a timer while the 3D scene warms up; the
   final release waits for the machine's SK.fireReady() (or a 9s bail-out
   so a slow device never traps anyone). On release, fill to 100%, fade
   the overlay out, swap body classes is-booting -> is-lit. While
   booting, body overflow is hidden.

2. FIXED HUD. A small fixed strip (bottom-left, safe-area padded) with
   three buttons and a readout, all VT323: "invert" (aria-pressed),
   "music on/off" (aria-pressed), "track >>" (skips tape, aria-label
   announces the current track) and a now-playing span "np - <name>".
   The HUD must survive the invert theme automatically (it inherits the
   flipped tokens; mix-blend handles the rest).

3. INVERT THEME. One body class, is-invert, flips every token: paper,
   ink, cut-out inversion, blend modes, the 3D shell casing (white
   plastic, lower roughness), and the meta theme-color. Persisted in
   localStorage ("sb_invert"), restored on load, toggled by the HUD
   button AND the console's SELECT pill through the bus.

4. AUDIO — the autoplay dance, done legally. Browsers block sound
   before a user gesture, so: start the track MUTED and rolling from
   the first frame (preload="auto", muted, play()) so it is fully
   buffered; attach capture+passive listeners for pointerdown/up, click,
   keydown, touchstart/end, wheel and scroll; on the first gesture try
   to unmute (currentTime back to 0 for a clean top-of-track), fade the
   volume up over ~0.9s in a 40ms interval; only a CONFIRMED success
   may disarm the listeners (wheel/scroll cannot grant activation, so a
   failed attempt must never cost the next real click). Respect the
   remembered preference in sessionStorage ("sb_sound"), pause on
   document.hidden, resume when visible. Single-flight the unlock
   attempt so overlapping tries cannot restore the wrong mute state.

5. THE DECK. Two tapes in a TRACKS array at the top of Site.tsx:
   tape 0 "reflections - the neighbourhood" (user song, volume 0.3)
   and tape 1 "sb theme - ambient loop" (10.7s numpy-synthesized A-minor
   loop, volume 0.42). Per-track volume because mastered songs sit lower
   than home-made loops. "track >>" cycles with a skip, never a
   crossfade: if rolling loud, restart the new tape from silence and
   fade up; if rolling muted, keep rolling muted; if paused, swap only.
   Remember the tape index per session ("sb_track") and align audio.src
   with it before anything plays.

6. SCROLL ENGINE. One requestAnimationFrame loop, three jobs:
   a) BACKDROP TONE: one fixed full-viewport .backdrop div whose gray
      level is interpolated every frame, so where a light section meets
      a dark one the tones BLEED across a 0.6-viewport band instead of
      hitting a hard seam. Invert flips the mapping.
   b) PER-ELEMENT DRIFT: each cut-out and type layer gets a depth
      coefficient (e.g. star +0.16, second star -0.13, CDs +0.15/-0.12,
      headline -0.05, bio +0.035); translate it by its distance from
      viewport center times depth. Skip when far off-screen.
   c) REVEALS: .rev elements start hidden; an IntersectionObserver
      (threshold 0, rootMargin "0px 0px -6% 0px") adds .is-shown once.
      Add a 900ms failsafe sweep that force-shows anything intersecting
      the viewport, so an observer misfire can never leave content
      invisible. All of it off under reduced motion.

7. SECTIONS (single <main id="top">):
   01 FRONT — dark paper. Giant two-line hero "shutter" / "bug." in
      huge tight Helvetica, two star cut-outs and a dice drifting
      around it, a scroll cue arrow that smooth-scrolls to #work.
   02 WORK — the machine (see spec 8).
   03 ABOUT — dark paper. "About me" headline between two drifting CD
      cut-outs and a two-paragraph bio (real text below), justified,
      ~44% width, centered.
   04 CONTACT — dark paper. "contact" + "me." echo of the hero, fanned
      business-card cut-out, and a row of six circular badge icons
      (mail + five socials) linking to the real URLs below.

8. THE MACHINE — the centerpiece. A real-time Three.js handheld console
   built entirely from primitives (no downloaded model):
   - RoundedBox shell 2.62 x 1.22 x 0.22 (dark #161616, roughness .52),
     widescreen bezel left-of-center, d-pad cross right, four cylinder
     face buttons in an xbox diamond (Y top, X left, B right, A bottom)
     each wearing a VT323 letter cap drawn on a canvas texture, two
     start/select capsule pills, a power LED sphere, two shoulder
     triggers on the top edge.
   - THE SCREEN: a 512x288 offscreen <canvas> is painted every frame
     (current poster or video, cover-fit, breathing zoom 1.05 + 0.02
     sin for stills, portrait sources pillarboxed, a brightness(1.22)
     lift to survive the shader, and a VT323-style timecode chip
     "ID - 03/10" bottom-left) and fed as a CanvasTexture into a CRT
     ShaderMaterial: barrel warp, RGB split growing toward the edges,
     scanlines, phosphor cell grid, a rolling brightness band, fine
     noise, glass vignette and an emissive lift uniform.
   - THE SCREEN IS THE LIGHT: every ~420ms read an 8x8 downscaled
     average of the screen canvas; drive uGlow, a screen-colored
     PointLight intensity, and an additive radial glow card behind the
     device from that average, so a bright frame really throws light
     on the shell.
   - CHANNELS: src/lib/works.ts drives the screen. Ten channels —
     channel 01 is the SOCIALS motion graphic (see spec 9), channels
     02-10 are generated film posters each with a 6-second Ken Burns
     mp4 loop. A rail readout bottom-right shows "01 /10", the work
     title's link, and an open-in-new-tab arrow.
   - WORKING PROTOTYPE. Invisible raycast hit planes parented to each
     control. Actions: d-pad left/right + shoulders = previous/next
     channel; A and START = open the current channel's link; B =
     pause/resume the reel (LED green only while actually playing);
     X = jump to channel 01 (socials); Y = shuffle; SELECT = flip the
     page invert through SK.toggleInvert. Press feedback: the control
     dips 0.022 units on a 0.16s sine and releases. Hover raycast sets
     a pointer cursor. Drag anywhere else rotates the device (clamped
     pitch), with a gentle idle sway after 2.6s of no interaction.
   - KEYBOARD: ArrowLeft/ArrowRight flip channels (with a little
     rotational nudge), X opens the link — only while the machine
     section is intersecting the viewport. Never hijack keys when an
     input/textarea is focused.
   - ENGINE HYGIENE: pixelRatio capped at 2, ACESFilmic tone mapping,
     sRGB output, transparent clear, camera pulls back on narrow
     aspects (z = max(4.4, 5.1/aspect)), IntersectionObserver pauses
     the rAF work when the section is off-screen, everything disposed
     on unmount, and a dev-only window.__machine debug hook
     (fire/pos/state) that is removed in cleanup.

9. THE SOCIALS REEL. Generate a ~22s, 960x540, 30fps, black-and-white
   motion graphic mp4 (Python + Pillow frames piped to ffmpeg, or
   matplotlib-free pure PIL): an intro starburst wipe, then five social
   cards — YOUTUBE @mayankforge / GITHUB e2sy / TELEGRAM ExploitArc /
   DISCORD invite / X @mayankbhaskarr — each with a platform tag, a
   huge VT323-style handle, a small note line, a sweeping highlight
   line, progress dots, white flash cuts, glitch slices and rotating
   star/CD/dice dressing; end on an outro card with the console control
   legend. Film grain, vignette and scanlines over everything, no color.
   Register it as channel 01 with a matching poster jpg and link it to
   github.com/e2sy.

10. CONTENT (bake this exactly).
    - Hero brand: "shutter" / "bug."
    - Bio, paragraph 1: "I'm a student from Purnea, Bihar, building
      things with AI and code. I like taking an idea from a rough
      sketch to something people can actually use, whether that's an
      open-source tool on GitHub, a free app I build and document on
      YouTube, or an AI gateway I'm planning from scratch. I'm in
      Class 11 studying PCM, and most of my time goes to school and
      building."
    - Bio, paragraph 2: "What I'm chasing is AI product engineering:
      full-stack projects where models do the heavy lifting and the
      interface stays simple. My code is on GitHub, my build videos are
      on YouTube as Mayank Ship, and I share what I'm learning on X.
      Keep it simple, ship often, and learn in the open."
    - Contact links: GitHub https://github.com/e2sy · YouTube
      https://www.youtube.com/@mayankforge · Telegram https://t.me/
      ExploitArc · Discord https://discord.gg/g4Qk9WRZB · X
      https://x.com/mayankbhaskarr · plus a mailto badge.
    - Archive titles: Socials, Night Shift, Soda City, Long Exposure,
      Paper Moon, Static, Grandstand, Monsoon Tape, Low Fidelity,
      First Light — each with a one-line sub like "bottles, buses,
      neon rain".

ASSET GENERATORS (write these into scripts/ and run them)
- gen_images.py (Pillow): starbursts, dice, flower rosette, two CDs,
  fanned business cards, mail icon, pixel-camera boot sprite, and ten
  grainy black-and-white film-poster "stills" with viewfinder furniture

- gen_audio.py (numpy): a seamless ~10.7s ambient loop in A minor —

- gen_badges.py (Pillow): six circular VT323 badge icons (mail + yt,

QUALITY BARS
- Mobile 390px: everything fits, nothing clips, the HUD wraps, the
  console stays in frame (camera pullback), badges keep margins.

Now build it all — code, scripts, generated assets, and a final summary
```
